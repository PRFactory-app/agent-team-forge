# .NET 11 RC 1 process APIs: AgentTeamForge research

**Research snapshot: 2026-09-26.** Source inspection only; no .NET 11 SDK installation, build, published-binary run, or platform test. Planning target is **.NET 11**, as requested; existing .NET 10 spike evidence remains valid only for its tested .NET 10 behavior. This report does not authorize changing that concurrent spike.

## Release and evidence boundary

Official [release index](https://github.com/dotnet/core/blob/main/release-notes/11.0/README.md), [RC 1 release note](https://github.com/dotnet/core/blob/main/release-notes/11.0/preview/rc1/11.0.0-rc.1.md), and [published release manifest](https://github.com/dotnet/core/blob/main/release-notes/11.0/preview/rc1/release.json) corroborate **11.0.0-rc.1**, released **2026-09-08**, runtime **11.0.0-rc.1.26425.128**, SDK **11.0.100-rc.1.26425.128**. On snapshot date RC 1 is latest release shown in index, **not GA**. [Microsoft's RC 1 announcement](https://devblogs.microsoft.com/dotnet/dotnet-11-rc-1/) explicitly states a **go-live support license** for production use; this is not a claim of GA stability. [Release index](https://github.com/dotnet/core/blob/main/release-notes/11.0/README.md) projects .NET 11 STS support 2026-11-10 through 2028-11-09; future GA/support dates are a schedule, not an observed GA release. RC 1 has prerelease API, package, tooling, regression, and platform risk.

**Version trap:** the [RC 1 libraries article](https://github.com/dotnet/core/blob/main/release-notes/11.0/preview/rc1/libraries.md) says its examples were checked against `Microsoft.NETCore.App.Ref@11.0.0-rc.1.26427.112`; [its build-metadata file](https://github.com/dotnet/core/blob/main/release-notes/11.0/preview/rc1/build-metadata.json) also names `26427.112`, whereas the public release manifest says `26425.128`. Therefore this article alone cannot prove a particular symbol shipped in the downloadable RC. Every API signature below was cross-checked in the [**published runtime tag's Process reference source**](https://github.com/dotnet/runtime/blob/v11.0.0-rc.1.26425.128/src/libraries/System.Diagnostics.Process/ref/System.Diagnostics.Process.cs), tag commit [`ab19415702aa8139d5369e47c73edb47343c34ad`](https://github.com/dotnet/runtime/commit/ab19415702aa8139d5369e47c73edb47343c34ad). Source/ref evidence is stronger than an unpinned `net-11.0` docs page or merged proposal, but still **not an installed-pack binary test**. Reconfirm with the pinned public SDK/ref pack before a compatibility claim. Earlier introduction dates below come from the [Preview 4](https://github.com/dotnet/core/blob/main/release-notes/11.0/preview/preview4/libraries.md), [Preview 5](https://github.com/dotnet/core/blob/main/release-notes/11.0/preview/preview5/libraries.md), [Preview 6](https://github.com/dotnet/core/blob/main/release-notes/11.0/preview/preview6/libraries.md), [Preview 7](https://github.com/dotnet/core/blob/main/release-notes/11.0/preview/preview7/libraries.md), and [RC 1](https://github.com/dotnet/core/blob/main/release-notes/11.0/preview/rc1/libraries.md) library notes; *all listed APIs are new in .NET 11, not .NET 10*. The runtime tag, rather than a main-branch proposal/PR, establishes RC 1 source presence.

## Decision matrix and next spike impact

| Feature | Decision | Proof / restriction |
| --- | --- | --- |
| .NET 11 targeting | **Investigate with bounded experiment** | Plan for RC 1; separately review major persistence/lifetime plan before implementation. If SDK explicitly approved/provisioned, candidate `global.json` SDK pin is **`11.0.100-rc.1.26425.128`** (verified public manifest), not undocumented `26427.112`. No SDK installation here. Preserve and compare .NET 10 evidence; retest package restore and published artifacts. |
| Run/capture and line reads | **Investigate** | Use only small version/doctor probes with timeout **and output-size enforcement**; use manual bounded draining if helper cannot enforce byte limit. Do not pass accepted-job client cancellation into worker capture. |
| Direct `SafeProcessHandle.Start`/wait and exit status | **Investigate, candidate for next headless fake-process slice** | Keep handle alive in independent daemon and dispose deterministically; test process death vs backend ack/final; inspect status as diagnostics, not completion. Never replace durable attempt-start transaction with process API call. |
| `StartAndForget` / `StartDetached` | **Defer for managed agents** | May help disposable launchers with explicit policy, not durable controlled jobs or interactive terminals. Never treat returned PID as ownership. |
| `KillOnParentExit` | **Investigate for explicitly accepted headless policy only** | Default off for interactive; test Windows Job Object and Linux direct-child/grandchild, service-manager/cgroup interaction. macOS unsupported; retain explicit platform policy. |
| `InheritedHandles` / standard handle overrides | **Investigate** | Minimal private child pipe with no leaked credential handles, concurrent launches and close/EOF tests. Do not put secret in argv/env unnecessarily; test selected terminal provider's own inheritance separately. |
| `StartSuspended`/`Resume` | **Investigate on Windows/macOS only** | Test binding and cleanup during suspended failure; Linux is explicitly unsupported. No interactive assurance unless provider offers verifiable same-child launch control. |
| `TryGetProcessById`, `SafeProcessHandle.Open` | **Do not use as proof of ownership** | May be diagnostics after matching persisted generation, start identity and backend/provider IDs. Unix `TryOpen` remains PID-racy. |
| POSIX signaling | **Investigate for proven direct child on Unix** | Test SIGTERM→wait→explicitly approved escalation; macOS/Linux signal differences; Windows use separate backend/native control. Turn interruption and agent stop must be different operations. |
| Native start callbacks | **Defer** | Only if tested Job Object or Unix launcher requirements exceed ordinary spawn APIs; avoid premature unsafe interop. |

The user has selected **.NET 11** for upcoming work. Align the [durable-core plan](../spikes/m0-durable-core-plan.md) with that target and the verified candidate SDK pin; implementation still requires independent plan review for its persistence/lifetime contract. SDK provisioning and runtime compatibility remain separate from the planning decision. Retain Host → Business → DAL and fake backend. Start transaction precedes *every* spawn/terminal launch; a suspended child narrows a later setup race but cannot close commit-to-spawn uncertainty. Do not modify concurrently running [interactive spike](../../spikes/m0-interactive/). For client crash survival, daemon and launched work cannot be inside killed bridge's kill scope; `StartAndForget` does not establish this. For daemon crash, handle/stdio cannot simply be recovered; surviving agent/terminal needs independently verified binding, or `needs_reconciliation`. Terminal server, Herdr pane, Windows tab, or macOS tab can be actual parent; do not auto-kill/restart live interactive TUI. Windows Job Objects, Linux process groups/cgroups, macOS GUI session and service manager are **different ownership domains**, never inferred from PID or `StartDetached`.

### Focused C# proof tests / gates

1. **RC compile + publish:** isolated C# harness targets `net11.0`, pinned public RC SDK and actual restored ref pack; compile every candidate signature, run JIT and *published* Native AOT on Linux. Capture warnings/package versions and binary identity. Repeat platform checks on **actual Windows/macOS** before claiming support. Existing .NET 10 experiments are baseline comparison, not evidence of RC support.
2. **Short-process boundedness:** stdout/stderr concurrent output, large output over cap, blocked child, malformed/Unicode argv, timeout and cancellation; check memory/time ceilings, descendants, streams, actual process reaping, result/status semantics. Do not run unbounded capture on real agent.
3. **Ownership/crash:** launch direct child and grandchild under approved headless policy, kill bridge vs daemon separately, compare `KillOnParentExit`, `StartDetached`, process tree/group/Job Object behavior; verify no second writer after restart; fake PID reuse/start-identity mismatch prohibits signal/adoption. Use barriers/abrupt kill, not sleep-only guesses.
4. **Suspend/handle:** Windows/macOS create suspended, set ownership, simulate failure before resume, release/clean up; Linux explicit unsupported case. Concurrent whitelist launches and intentional inherited pipe/credential leak checks. Terminal-owned TUI requires **separate real provider test**, not headless inference.
5. **Exit vs completion:** SIGTERM/SIGKILL (Unix), Windows supported signal only, normal exit, failed result write, model self-report, unrelated human turn; assert no completed job without correlated authoritative backend record. Test turn interrupt keeping live TUI separate from authorized agent stop.

Platform support gate remains real Claude/Codex TUIs in Herdr/Linux and visible selected Windows/macOS tabs with verified control/result, human input and client/daemon restart; lack of platform machine means **blocked**, not passed. Explicit setup choice never silently changes to headless. Native AOT needs real package and native-asset measurements, not source inference: [Native AOT deployment limitations](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/), [System.Text.Json source-generation guidance](https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/source-generation), [official MCP C# SDK](https://github.com/modelcontextprotocol/csharp-sdk), and [Microsoft.Data.Sqlite package](https://www.nuget.org/packages/Microsoft.Data.Sqlite/) do **not together prove** RC 1 MCP tool-registration trimming, role-specific hosting, SQLite native asset load/RID compatibility, or code size. Pin tested packages only after restore; publish and invoke MCP initialize/tools/call, SQLite transaction/recovery, JSON serialization in AOT. Record trim warnings, platform prerequisites, startup/PSS, and JIT comparison. No generic .NET 11 feature catalogue is warranted; RC 1 JSON union/closed-type work is not needed for current bounded IPC protocol ([RC 1 libraries note](https://github.com/dotnet/core/blob/main/release-notes/11.0/preview/rc1/libraries.md)).
