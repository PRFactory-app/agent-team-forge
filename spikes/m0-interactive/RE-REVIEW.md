# Independent GPT re-review — interactive M0 safety repair

**Verdict (2026-09-26):** Original review's core fixes are real, but **do not promote either complete interactive adapter as safe yet**. Codex has a promising **bounded reusable subset** (atomic claim/fence rules, native attempt IDs and turn correlation, fail-closed *recognized* history errors, read-only diagnostic method gate, and binding checks); reuse these with the qualifications below, not as an approved end-to-end dispatch contract. Full spike/M0 gate remains **blocked**: Claude still accepts and completes unverifiable-origin work through its normal `send` path, Claude native cancel is absent, and the repaired Codex/Herdr path has remaining safety and qualification gaps. No live session was controlled or destroyed in this review.

This is an independent review of actual source and tests, not acceptance of FIXES.md's dispositions or of a passing test count. Prior `CODE-REVIEW.md`, `FIXES.md`, `README.md`, and `REPORT.md` remain unchanged. Paths below are relative to this spike. Code was not edited. No Git operations, installs, model calls, live Herdr commands, teardown, or credential/session inspection were performed. Evidence files were not opened or published; implementer's live claims in FIXES.md remain claims rather than reproduced live results.

## Remaining blockers and qualifications, ranked

1. **High — stopped-session deletion is not ownership-proven.** `src/AtfSpike/Herdr/HerdrOwnership.cs:23-42` permits deletion whenever a session with the saved name is listed as stopped, without verifying the owner-labelled workspace or any persisted provider identity. `src/AtfSpike/Launch.cs:102-129` then runs global `session delete` by name. If the owned session was removed and another stopped session occupies that name, deletion targets the replacement. Random names make collision unlikely, but this is still destructive action based on a reusable name. Even a formerly owned stopped session is not currently proven owned by this check. `tests/AtfSpike.Tests/HerdrOwnershipTests.cs:64-71` expressly approves this bypass; it is not a negative replacement-session test. Refuse deletion without verifiable stopped-session provenance; if Herdr cannot supply it, leave the stopped session for manual handling. Do not test against live resources.

2. **High — launch ownership intent races across CLI processes.** `src/AtfSpike/Launch.cs:16-37` reads state *outside* the lock, then its `Update` overwrites `HerdrSession`/`SessionOwnership` without rechecking that no other `session-up` persisted intent. Two processes can both observe no state, persist different names, each start a Herdr server, and overwrite each other's recorded provenance (`:38-47`). This can orphan sessions and make subsequent teardown refer to a different launch. `src/AtfSpike/State/SpikeState.cs:137-158` serializes individual updates, not the earlier read/decision. Add atomic absent-state compare-and-create under one lock, preserve the winner's intent, and test two-process `session-up` with fake provider responses. Existing two-process test covers *job claims*, not launch.

3. **High — successful but incomplete history replies authorize Codex dispatch.** `src/AtfSpike/Codex/CodexThreadEvidence.cs:9-11` maps a missing/non-array `data` to an empty turn list. `src/AtfSpike/CodexCommands.cs:255-295` accepts that as `HistoryState.Available` without validating page shape, thread identity, cursor or turn IDs; `:341-360` treats empty turns plus `thread/read` `idle` as send authorization. A partial or changed `thread/turns/list` response on an established thread can therefore erase evidence of busy/foreign work even though the recognized *error* path now fails closed. Require a validated complete history envelope (and nonempty usable IDs); malformed/missing data is `Unavailable`. Test an idle established thread with a successful missing/malformed history page. The `ProvenEmpty` exception in `CodexHistory.Classify` (`CodexThreadEvidence.cs:58-69`) additionally infers "never-used" from local `HistoryEstablished=false` plus idle/empty preview, not independent backend history proof; keep it version-specific and re-qualify before relying on it as a safety gate.

4. **High — Claude origin/cancel remain unsafe on executable paths, not merely unsupported in prose.** `src/AtfSpike/Claude/ClaudeHookLog.cs:120-139` attributes the first matching post-claim prompt by tag, hash, and timestamp, but cannot distinguish a human typing identical text from inbox delivery. `src/AtfSpike/ClaudeCommands.cs:149-219,222-249` still exposes ordinary `send`, folds that evidence into `Completed`, and frees the dispatch fence via `src/AtfSpike/Delivery/DispatchClaims.cs:57-72`. `ClaudeCommands.cs:263-289` still offers `--send-esc-unverified`, which injects a keystroke while returning unsupported. Reporting ambiguity and exit 8 is honest, **not** safe prevention of incorrect completion or a native targeted cancel. Keep Claude out of a safe-adapter promotion path; separate explicit exploratory use from managed dispatch and prohibit unsafe cancellation as a managed operation until origin and native stop/interrupt contracts exist. Claude hook failure markers do not solve origin.

5. **Medium-high — the bound Codex thread is not independently tied to the visible TUI.** `src/AtfSpike/CodexCommands.cs:89-103,133-179` chooses the sole loaded non-helper thread on a per-agent app-server and separately finds a TUI process with `--remote` pointing to that socket. Subsequent checks (`:224-242`; `Codex/CodexThreadEvidence.cs:72-100`) prove the process, pane, socket owner and sole loaded thread, but do not obtain a native TUI-client-to-thread association. A surviving remote TUI process no longer attached to that thread would still satisfy these facts if the thread remained loaded. This is a limitation of the observed 0.157.1 control API, not evidence that misrouting happened. Before treating completion as belonging to the visible agent, either verify a native client/thread association or constrain and test TUI disconnect/reconnect and thread-switch behavior fail-closed; keep Herdr pane metadata advisory.

6. **Medium-high — deadlines and bounds do not cover whole Codex transport.** `src/AtfSpike/Codex/JsonRpcPeer.cs:88-112` creates its request deadline only *after* `SendAsync`, which can wait for `_sendLock` or stall in transport (`:131-151`) with `CancellationToken.None` at `CodexCommands.cs:363-369,509,556`. A send exception before deadline creation also leaves `_pending[id]` registered (`:91-103`); max-pending check is a count-then-insert, not an atomic quota. `--timeout` is a wait-loop limit, not a whole-operation deadline (`CodexCommands.cs:414-470`). `src/AtfSpike/Herdr/HerdrCli.cs:45-62` starts unbounded `ReadToEndAsync` output capture before its 120-second process wait. Bound write/connect/lock acquisition and total operation; classify timeout or cancellation after possible write as uncertain, never unsent. Bound CLI output and add stalled-send/flood fake tests. Existing `JsonRpcPeerTests.cs:97-148` tests a stalled **response** and an 8-entry inbound queue, not a stalled send or CLI output. An oversized WebSocket frame also throws `InvalidDataException` (`UdsWebSocketTransport.cs:84-90`); `JsonRpcPeer.cs:155-168` completes pending requests in `finally`, but the read-loop task faults on disposal rather than cleanly reporting a protocol failure.

7. **Medium-high — human-wins check is observational, not an atomic idle-to-send fence.** `src/AtfSpike/CodexCommands.cs:341-370` reads history, checks idle/foreign, subscribes, then calls `turn/start`; a human TUI turn can begin between those operations. `:518-544` likewise reads idle/history before clearing a persisted pause, with no backend idle lease or second atomic validation. The persisted pause is valuable after a foreign turn is observed; it cannot prevent this unobserved overlap. Test this exact fake-backend interleaving and define a supported serialize/abort/uncertain policy; do not claim strict human-wins from the Herdr-typed completed-turn demonstration. Real human T05/T15 remain unrun.

8. **Medium — hook failure privacy/replay claims remain qualified.** `src/AtfSpike/Claude/ClaudeHookRunner.cs:41-57` checks file size before append without a cross-process lock, so concurrent hooks can exceed 16 MiB; `:78-87` uses an unbounded `File.AppendAllText` failure marker with no explicit 0600 mode or fsync (its containing private directory limits traversal in the ordinary case). If marker creation fails, only a nonzero hook exit remains, and `ClaudeCommands.cs:132-140,172-177,235-247` cannot prove complete evidence. Positive: hook input is bounded and failure returns nonzero. Do not claim durable outage replay or power-loss guarantees from this path. `State/SpikeState.cs:137-171` now flushes state and fsyncs its directory; power-loss and missing-state-after-acceptance behavior remain untested, not SQLite-equivalent.
