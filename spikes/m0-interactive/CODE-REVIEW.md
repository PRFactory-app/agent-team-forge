## Blocking findings (ranked)

1. **High — concurrent sends can deliver same job twice.** `src/AtfSpike/ClaudeCommands.cs:137-159`, `src/AtfSpike/CodexCommands.cs:235-265`, `src/AtfSpike/SpikeContext.cs:85-90`: `Accept` and busy/history checks happen before `Set(Dispatching)`, which unconditionally writes state. Two CLI processes sending same accepted job can both see `Accepted` and idle, both persist `Dispatching`, then both write to inbox or call `turn/start`. File locking serializes individual updates, not the check-and-claim. Different job IDs for one conversation race too. Consequence: duplicate or concurrent physical work despite successful unit tests and crash-barrier evidence. **Correct:** atomic compare-and-claim of unattempted job *and* per-session dispatch/idle fence under one lock, with one generation/correlation per attempt; recheck state after claim. Add two-process fake-transport race test. No blind retry of claimed attempts.

2. **High — human/foreign input can forge job completion.** `src/AtfSpike/Claude/ClaudeHookRecord.cs:40-45`, `src/AtfSpike/Claude/ClaudeHookLog.cs:74-88`, `src/AtfSpike/Codex/CodexThreadEvidence.cs:21-27`, `src/AtfSpike/CodexCommands.cs:241-245`: any text containing `[atf-job:<id>]` becomes job evidence; Codex even falls back to this tag when native `clientId` is missing. A human typing that tag into TUI and completing a turn can make a merely accepted or uncertain job `Completed` without that job's machine message being delivered. Claude hooks prove session/turn lifecycle, **not origin of tagged prompt**. **Correct:** for Codex require native `clientId` and bound turn/attempt ID, refuse conflicting IDs; for Claude require a demonstrably trusted delivery-to-hook binding or classify ambiguous tagged turns as foreign/needs reconciliation. Test forged tag before delivery and during an uncertain attempt. Keep model text informational.

3. **High — terminal teardown relies on a reusable name, not ownership.** `src/AtfSpike/Herdr/HerdrCli.cs:63-76`, `src/AtfSpike/Launch.cs:10-21`, `src/AtfSpike/Program.cs:121-139`: `EnsureServer` accepts any already-running session with the fixed name; `Teardown` checks only that same name, then stops and deletes the whole session. If a pre-existing/unrelated session has that name, `session-up` can reuse it and `teardown` can destroy its tabs. A local state file saying the name is not provenance. **Correct:** allocate unique owned session identity, record and verify provider/server ownership before teardown; refuse existing unproven session and delete only proven-owned resources. Do not test this on live sessions; use fake Herdr responses.

4. **High — Codex can send through an unverified/stale TUI binding.** `src/AtfSpike/CodexCommands.cs:253-265`, `src/AtfSpike/Launch.cs:45-69`, `src/AtfSpike/State/SpikeState.cs:18-25`: failed pane/terminal binding is logged as `binding_warning` and `turn/start` still executes. App-server has no persisted PID/start identity or verified server ownership; one loaded thread at launch does not prove later socket/thread/pane is still the intended live interactive agent. After stale metadata, pane replacement, or socket reuse, a machine prompt can target a detached/wrong conversation while being reported acknowledged. **Correct:** fail closed on binding failure, verify app-server process/socket/thread and TUI association before sending/interrupting, and surface uncertainty if not provable. Add stale-pane/socket fake test. Herdr status alone remains advisory.

5. **High — human-wins pause is not implemented.** `src/AtfSpike/ClaudeCommands.cs:145-149`, `src/AtfSpike/CodexCommands.cs:247-251`, `src/AtfSpike/Claude/ClaudeHookLog.cs:77-84`, `src/AtfSpike/State/SpikeState.cs:59-66`: busy check only sees an *active* turn; completed human/untagged turn leaves no persisted `foreign_busy` state or authorized verified-idle reconciliation. Next automatic `send` proceeds when idle, contrary to T15 policy. `--allow-busy` additionally bypasses even active-turn/approval safeguards without authorization or auditable evidence; for Claude an inbox message during a turn may not emit its assumed submit hook. **Correct:** persist foreign observation and fence follow-ups until explicit authorized reconciliation; do not treat generic `--allow-busy` as permission/idle proof. Test completed human turn followed by attempted machine send. T05/T15 are unrun, not passes.

6. **Medium-high — history errors collapse to empty evidence and can authorize a send.** `src/AtfSpike/CodexCommands.cs:195-219,234-265`: every first-page JSON-RPC error, not just the two observed pre-first-turn errors, returns `[]`. If history fails on a materialized thread while `thread/read` says `idle` (known to lag turns), a new accepted job can be sent despite unobserved active/foreign work; a matching observed turn can also be missed. **Correct:** allow only verified pre-first-turn error codes in proven empty-thread context; otherwise make history unavailable a blocked/uncertain state, never an idle authorization. Add error-on-established-thread test.

7. **Medium-high — unrestricted diagnostic RPC bypasses dispatch policy.** `src/AtfSpike/Program.cs:81-82`, `src/AtfSpike/CodexCommands.cs:369-378`: `codex-rpc` accepts arbitrary method and JSON including mutating `turn/start` or `turn/interrupt`, without intent journal, busy/identity checks, or job idempotency. Local operator-only CLI is a spike limitation, not an authorization boundary. **Correct:** constrain diagnostic command to read-only allowlisted methods or explicitly isolate unsafe probes from normal managed sessions; never advertise it as safe control. Add bounded method-rejection test if kept.

8. **Medium-high — hook/result and IPC bounds do not establish durable outage replay.** `src/AtfSpike/Program.cs:8-34`, `src/AtfSpike/ClaudeCommands.cs:106-120`, `src/AtfSpike/Codex/JsonRpcPeer.cs:44-77,91-105`, `src/AtfSpike/Codex/UdsWebSocketTransport.cs:62-91`: hook reads all stdin, silently swallows append failures and exits 0; each status/wait rereads whole ever-growing hook log. JSON-RPC has unbounded inbound channel/pending waits, callers use `CancellationToken.None`, and `--timeout` does not bound a stalled request/connect. WebSocket incoming frame is capped at 16 MiB, but outgoing instruction, queue, log and state histories are not. During daemon absence/full disk a Claude completion can be lost without an observable error; a chatty/stalled peer can exhaust memory or hang the harness. **Correct:** bound hook input/log retention, surface spool failure and explicit uncertain/unsupported replay, impose RPC request deadlines and bounded inbound/output/backpressure; test hook write failure and stalled/flooding fake peer. Do not claim zero result loss from these hooks.

## Nonblocking observations / claim corrections

- **File state is process-kill tolerant in tested windows, not power-loss durable.** `src/AtfSpike/State/SpikeState.cs:83-107` flushes temporary file and atomically renames under a lock, but does not sync parent directory; initial `Read()==null` is treated as empty state. State and Claude settings use default creation modes; observed `.run/spike/state.json` and `.run/spike/claude-cl1.settings.json` were mode `0644` under mode `0755` directories. `src/AtfSpike/SpikeContext.cs:17-25` creates run directory without a private mode. State holds result text and session/socket identifiers. Use private directory/files and fsync or qualify crash-only guarantee; never call this SQLite-equivalent durable acceptance. Local same-user access is not an OS sandbox.
- **Credential/environment claim is narrower than a safe launcher.** `src/AtfSpike/Herdr/LaunchEnvironment.cs:12-24` removes observed named prefixes but forwards all other inherited variables (including possible backend/API credentials) to a persistent Herdr server and panes. Clean run2 demonstrates removal of inspected session-context variables only. Product needs explicit environment allowlist. Hook `src/AtfSpike/Claude/ClaudeHookRecord.cs:16,53-59` also stores `transcript_path`/cwd and up to 4,000 characters of model result: redacted prompt/token is not fully publication-safe diagnostics.
- **Cancel evidence must remain scoped.** `src/AtfSpike/ClaudeCommands.cs:213-251` sends Esc, returns exit code 0, retains `BackendAcknowledged` if no hook. Output says unverified; do not interpret command success as supported targeted native cancel. Run2 shows advisory Herdr `done`, then timeout, then reconciliation only after another prompt. Codex run2 shows one correlated `turn/interrupt` and final `Interrupted`; actual running-tool interruption/child cleanup and separately authorized agent stop were not tested or implemented. T08 as a whole is not passed.
- **Approval observation is conditional.** `src/AtfSpike/CodexCommands.cs:290-337` only notices server requests on a connected `--wait` peer, prints one transient event, and does not persist blocked state; Claude hook view marks blocked but job remains `BackendAcknowledged` on timeout. Nothing auto-approves (good). Codex live approval and no-lead approval state remain unverified/unsupported, not a pass.
- **Launch attempt intent is not recorded before terminal side effects.** `src/AtfSpike/ClaudeCommands.cs:26-44`, `src/AtfSpike/CodexCommands.cs:29-49`, `src/AtfSpike/Launch.cs:10-21,29-38` create workspace/tab before persisting a launch generation or ownership marker. A crash can orphan a tab; fixed-name state prevents some automatic relaunches, but does not prove safe adoption or T19 lost-launch-response idempotency. Appropriate for exploratory spike only, not product crash contract.
- **Safety tests are lean but miss critical paths:** two-process duplicate claim, tagged human spoof, foreign-busy after completion, history error on established thread, stale binding, unexpected hook write failure and timeout/queue bounds. Existing tests exercise pure reconciler, wire, hook fold and transport, not these end-to-end fences. No need for prose assertions or extra architecture projects.
