# Slice 9a wiring

This commit supplies account limit detection, durable account windows and parked job lineage, bounded claim reservations, and a conservative readiness DTO. It does not activate parking or advertise the new capability until the following call sites are wired and verified.

1. src/AgentTeamForge.DAL/Migrations/Schema.cs:Apply: register AccountAdmissionMigration.Sql as the next migration after concurrent slices settle. AccountWindowStore deliberately fails if this schema is missing. Tests apply AccountAdmissionMigration.Apply directly.
2. src/AgentTeamForge.Business/Features/Jobs/DispatchJob.cs:ClaimLoopAsync: before JobStore.BeginNextAttempt, resolve the job's configured backend/account binding and call AccountAdmission.CanStart. A blocked account must leave its queued intent intact while unrelated accounts can claim. The current BeginNextAttempt chooses the oldest intent without a backend predicate, so add an eligible-account predicate to the store's claim SQL in the integration patch. Do not claim then fail a blocked attempt.
3. DispatchJob.RunAttemptAsync: in the BackendEvidence.Error path, use Claude InteractiveTranscriptReader.ApiError's Code and Message, or Codex/Pi nonzero-exit/API error evidence, to call AccountAdmission.ParkIfLimited before terminal failure. Only pass backend-owned error evidence, never user prompts. Persist a saved session ID and account binding; terminate/confirm the owned turn and release its running slot. The park state is separate from job failure. Preserve the same backend, model, cwd and session on resume; do not substitute an account or model.
4. Daemon startup / recovery (src/AgentTeamForge.Host/Hosting/DaemonCommand.cs and the PRFactory tick): reconcile AccountWindowStore.Resuming() against durable follow-up acceptance before retrying. For each AccountAdmission.Due(now) item, reserve with TryBeginResume, submit one same-session follow-up under a fixed idempotency key derived from the parked job, then ResumeRecorded; on a known no-effect failure call RetryResume. A reset without a timestamp remains parked until PermitAccountRecovery is explicitly invoked for that configured account. Hold PRFactory team completion while any member park is open.
5. src/AgentTeamForge.Host/Features/PRFactory/PRFactoryWorkItems.cs:TickAsync: set a separate accepted-team limit. Reserve one AccountAdmission.ReserveClaim token before each poll/claim allowance, and release it after the claimed item is durably inserted with PRFactoryTeamStore.CreateIfAbsent (or after no claim). Count only free admission budget in polling. Its transaction counts existing claimed teams plus outstanding reservations, including parks and waits; full backlog does not fail already accepted work. Add separate bounded child/command and recipe free-room/iteration checks when those paths are integrated.
6. src/AgentTeamForge.Host/Features/PRFactory/PRFactoryHeartbeat.cs:RunAsync, PRFactoryClient.RegisterMachineAsync and HeartbeatMachineAsync: collect real read-only CLI authentication/model probes and call PRFactoryReadiness.Report. Its absent probes report sign_in_unverified or model_unverified; only advertise readiness-parking-v1 for combinations whose install, auth, model, launch mode and resume checks passed. Add the readiness payload to registration/heartbeat DTOs in the serial connector patch. Never infer signed-in from an installed executable.
7. src/AgentTeamForge.DAL/Features/Jobs/PruneJobs.cs: pin all account_parks with state other than resumed and their parent accepted teams, plus other pending publication/upload/wait receipts before deleting local state.

No PRFactory server files, shared ATF dispatch/catalog/connector files, or live services were changed here.
