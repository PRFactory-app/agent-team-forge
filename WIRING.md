# Slice 5-core integration

Core classes are intentionally not registered or called by the connector yet.

- `DAL/Migrations/Schema.cs:Apply`: append `PRFactoryWorkspaceMigration.Sql` to the `Migrations` array and increment `CurrentVersion` in the serialized wave migration order. Tests apply this unregistered SQL directly.
- `Hosting/DaemonCommand.cs:RunAsync` composition (before the heartbeat callback constructs `PRFactoryWorkItems`): register one `PRFactoryWorkspaceStore`, one disposable singleton `TeamWorkspace`, and `PRFactoryWorkspace`. The singleton serializes Git workspace mutations. The daemon must remain the sole writer.
- `PRFactoryWorkItems.cs:AdvanceCoreAsync`: after slice 4 confirms authority, before any lead/child submission, call `PrepareAsync(WorkspaceRequest)`. Key by connection/work-item acceptance; supply the configured private state workspace root, authorized nullable repository identity, mapped absolute checkout, exact expected origin URL, default/base branch, optional authoritative base SHA, publish branch, and declared managed member order. Map prior implementation branch+SHA first, then StartFromBranch+StartCommitSha, then ProjectInit/PublishBranch. Continuations without authoritative SHA fail visibly. New ProjectInit branches fall back to base when the publish branch does not exist. This is single-repository only.
- `PRFactoryWorkItems.cs:SubmitMember`: use snapshot LeadPath or the member Path as `Cwd`, with `Worktree=false` (already isolated, including read-only phases). Do not make a second generic worktree from incidental HEAD. Paths and immutable choices are persisted before this call. Keep ReadOnly in the prompt/backend execution policy; isolated checkout is not an OS sandbox.
- `FollowUpJob.cs:Execute`: retain this Cwd and all existing backend/session options; do not create or repin a workspace for resumed turns. Generic JobWorktree now requires a persisted full SHA and validates its ancestry on restart while preserving branch-switch behavior.
- `PRFactoryWorkItems.cs:AdvanceCoreAsync`: when all child turns are complete and lead is quiescent, authority-check, then call `IntegrateChildrenAsync` for writable Git workspaces. Do not integrate read-only or scratch workspaces. Prevent concurrent lead/follow-up dispatch throughout integration. Children integrate in declared order, with clean committed files only. Merge commits preserve the entire child range from StartingSha (the execution base, which can differ from BaseSha on continuation). An intent records child head and before/after SHAs before advancing the lead ref. Conflicts leave checkouts unchanged and throw `WorkspaceConflictException.Files`; report failure/needs-attention, never auto-resolve. Dirty output remains in place and blocks integration.
- `PRFactoryWorkItems.cs:AdvanceCoreAsync` / slice 2 collector: call `GatherDocuments` with explicit relative text deliverables per completed child. Staging is `documents/child-<order>/<relative-path>`; identical retry succeeds, changed bytes fail. Do not auto-promote these files. Resume one idempotently keyed lead finalization turn in LeadPath, with staging paths and instruction to choose canonical phase documents and test the integrated code. Persist that turn through existing team member turn storage before dispatch.
- `PRFactoryWorkItems.cs:FinishAsync`: wait for integration, document gathering and lead finalization before artefact freeze/publication. Consume the saved workspace base/start/internal/publish branch and LeadPath, never the mapped developer checkout. Slice 6 supplies publication; slice 7 supplies drift/WIP; neither is implemented here. Keep workspace rows and paths pinned until final receipts/retention permit owned cleanup.

Remote identity matching is exact and intentionally rejects aliases; configure the approved origin spelling. Git 2.38+ `merge-tree --write-tree` is required. All core Git operations are bounded; connector authority and cancellation must be checked between operations. An operation already in progress finishes or times out; no remote publication occurs here. Scratch requires explicit authorized null repository input; it creates private directories without running Git.

Run the opposite-family review during integration; this worker was explicitly instructed not to spawn agents.

Fetched commits are pinned under `refs/atf/workspace-start/*` in the mapped repository so unrelated fetches cannot replace the selected head and garbage collection cannot remove the recorded start. These owned refs are retained with workspace evidence; later retention work must account for them before pruning.
